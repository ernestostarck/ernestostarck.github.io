Proyecto 1

Productividad

Zenith Flow

Aplicación web de productividad con tablero Kanban, panel de estadísticas y persistencia local con IndexedDB para simular un flujo serverless sin exponer una base de datos externa.

Contexto: Interfaz oscura con enfoque glassmorphism para organizar tareas personales y de equipo con una experiencia visual clara.

Problema: Necesidad de una base de productividad que permita seguir trabajo, prioridades y estado sin depender de servicios externos.

Solución: Tablero Kanban con arrastrar y soltar, métricas visuales, búsqueda y filtrado por prioridad, y editor de tareas con modal y checklist.

Decisiones técnicas: React 18 con Vite, React Bootstrap, Bootstrap 5, Bootstrap Icons e IndexedDB para persistencia local en el navegador.

Validación: Proyecto orientado a simulación de flujo serverless y operación local persistente en el navegador.

Impacto: Organización visual de tareas, seguimiento más rápido y datos guardados localmente sin base de datos remota.

Tecnologías:
React Vite Bootstrap React Bootstrap Bootstrap Icons IndexedDB

Proyecto 2

Clinical DSS

MedDecide DSS

Sistema de soporte a decisiones clínicas orientado a portafolio técnico, construido con Next.js App Router y rutas API serverless para simular triaje, diagnóstico diferencial e interacciones farmacológicas.

Contexto: Demo educativa de un flujo clínico realista para triaje, diagnóstico diferencial y revisión de interacciones farmacológicas.

Problema: Necesidad de mostrar cómo un panel clínico puede priorizar pacientes, calcular puntajes rápidos y resumir hallazgos sin depender de infraestructura pesada.

Solución: Dashboard con cola de pacientes, nueva evaluación clínica, calculadoras qSOFA, CURB-65 y CHA2DS2-VASc, y tres endpoints serverless consumiendo una base de conocimiento local.

Decisiones técnicas: Next.js 16 con App Router, React 19, API Routes, Lucide React, CSS global custom y base estática en JavaScript; el panel usa una visualización SVG manual para la distribución de triaje.

Validación: Flujo en paralelo hacia /api/triage, /api/diagnose y /api/interactions para mantener baja latencia percibida.

Impacto: Experiencia clara para demo técnica, reglas clínicas visibles y una arquitectura fácil de extender con persistencia o autenticación posterior.

Tecnologías:
Next.js React 19 API Routes CSS custom Knowledge Base JS

Repositorio disponible en GitHub

Proyecto 3

Automatización fullstack

SheetFlow Automation Hub

Plataforma fullstack para automatizar procesamiento de planillas XLSX con trazabilidad por corrida, aislamiento lógico por empresa y operación auditable de extremo a extremo.

Contexto: Operación con planillas heterogéneas provenientes de upload directo y URL remotas (OneDrive, SharePoint, Google Sheets).

Problema: Flujo manual frágil, baja observabilidad y dificultad para repetir resultados de manera consistente entre empresas.

Solución: Endpoint único POST /api/automation/run con backend Node como orquestador y motor Python para ejecución de negocio.

Decisiones técnicas: Separación estricta Frontend/API/Python, persistencia de corridas en PostgreSQL y normalización de errores para consumo de UI.

Seguridad y operación: Sesiones HTTP-only, CORS restringido, Helmet, control de upload XLSX y limpieza de temporales por corrida.

Impacto: Procesamiento repetible y auditable, menor fricción operativa y base preparada para escalar a colas asíncronas.

Tecnologías:
React 18 Vite Node.js Express PostgreSQL Python

Repositorio disponible en GitHub

Proyecto 4

Automatización táctica

Sistema de Reuniones - Tutorías UFT (Google Apps Script)

Aplicación web en GAS para administrar personas, disponibilidad horaria y agendamiento de reuniones con Google Meet en el Programa de Tutorías UFT.

Contexto: Coordinación manual de tutorías con poca trazabilidad, validaciones débiles y alta fricción operativa.

Problema: Agendamientos fuera de reglas (feriados, fines de semana, bloques no válidos) y riesgo de desorden en reservas.

Solución: Routing por rol, disponibilidad en Google Sheets, bloqueo de concurrencia con LockService y creación de eventos con Google Meet.

Decisiones técnicas: Arquitectura server-side en Apps Script para despliegue rápido, bajo costo y adopción inmediata por equipos académicos.

Impacto: Menor carga administrativa, mejor control de agendas y trazabilidad de cambios en el programa.

Escenario ideal: Operaciones institucionales que necesitan automatización confiable sin sobreinfraestructura.

Tecnologías:
Google Apps

Project 2

Clinical DSS

MedDecide DSS

A clinical decision support system built for a technical portfolio, using Next.js App Router and serverless API routes to simulate triage, differential diagnosis, and drug interaction checks.

Context: An educational demo of a realistic clinical flow for triage, differential diagnosis, and medication interaction review.

Problem: The need to show how a clinical dashboard can prioritize patients, compute quick scores, and summarize findings without heavy infrastructure.

Solution: Dashboard with a patient queue, new clinical assessment flow, qSOFA, CURB-65, and CHA2DS2-VASc calculators, plus three serverless endpoints backed by a local knowledge base.

Technical decisions: Next.js 16 with App Router, React 19, API Routes, Lucide React, custom global CSS, and a static JavaScript knowledge base; the dashboard uses manual SVG visualization for triage distribution.

Validation: Parallel requests to /api/triage, /api/diagnose, and /api/interactions keep perceived latency low.

Impact: Clear technical demo experience, visible clinical rules, and an architecture that is easy to extend with persistence or authentication later.

Technologies:
Next.js React 19 API Routes Custom CSS JS Knowledge Base

Project 3

Fullstack automation

SheetFlow Automation Hub

Fullstack platform that automates XLSX processing with run-level traceability, logical tenant isolation, and auditable end-to-end operations.

Context: Heterogeneous spreadsheets from direct uploads and remote URLs (OneDrive, SharePoint, Google Sheets).

Problem: Fragile manual flow and low observability for repeatable outcomes.

Solution: Single endpoint POST /api/automation/run with Node orchestration and a Python business engine.

Technical decisions: Strict separation between Frontend/API/Python, run persistence in PostgreSQL, and normalized errors for UI consumption.

Impact: Repeatable and auditable processing with lower operational friction and a path to async queues.

Project 4

Tactical automation

Meeting Management System - UFT Tutoring Program (Google Apps Script)

Web app in GAS to manage participants, availability, and meeting scheduling with Google Meet in the UFT Tutoring Program.

Context: Manual tutoring coordination with poor traceability and weak validations.

Problem: Bookings outside the rules and a high risk of scheduling disorder.

Solution: Role-based routing, availability stored in Google Sheets, concurrency control with LockService, and event creation with Google Meet.

Technical decisions: Server-side Apps Script architecture for quick deployment, low cost, and immediate adoption.

Impact: Lower administrative load, better agenda control, and program change traceability.

Ideal scenario: Institutional operations that need reliable automation without extra infrastructure.

Technologies:
Google Apps
